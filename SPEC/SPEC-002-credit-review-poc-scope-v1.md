# 授信智能合规审查平台 PoC 范围规范 V1.0

**编号：SPEC-002**  
**版本：V1.0**  
**状态：APPROVED**  
**评审结论：2026-08-10 用户评审通过**  
**上位规范：[SPEC-001 授信智能合规审查平台 V1.0](./SPEC-001-credit-review-platform-v1.md)**  
**适用里程碑：单机纵向薄切片 PoC**

## 1. 文档目标

本文档把 SPEC-001 的长期产品目标收敛为可在 Windows 单机完成、可演示、可测试的第一阶段 PoC。PoC 用于验证授信材料解析、事实抽取、矛盾处理、制度检索、规则校验、风险解释、人工复核和报告生成能否形成闭环。

本文档只定义 PoC 的业务范围和验收边界；技术架构见 [SPEC-003](./SPEC-003-credit-review-architecture-poc-v1.md)，接口与数据契约见 [SPEC-004](./SPEC-004-credit-review-contracts-poc-v1.md)，评测方案见 [SPEC-005](./SPEC-005-credit-review-evaluation-poc-v1.md)。

在本规范进入 `APPROVED` 前，不得开始正式代码开发。

## 2. 与 SPEC-001 的关系

- SPEC-001 继续作为长期产品总规范，正文不得因 PoC 收窄而删除或改写。
- 本规范仅覆盖一般对公/小微企业流动资金贷款的单机演示闭环。
- PoC 暂不采用 SPEC-001 中的 PostgreSQL、Milvus、Redis、MinIO、MCP、PaddleOCR 和 Docker Compose，也不一次完成 290 个长期评测样例。
- 发生冲突时，PoC 实施以 SPEC-002～005 为准；未被明确收窄的业务原则继续沿用 SPEC-001。
- PoC 验证通过不等于生产上线条件满足。

## 3. 产品定位与成功定义

产品定位保持为 **AI Credit Review Copilot**：AI 提供审查辅助，不执行最终授信审批。

PoC 成功必须同时满足：

1. 两个合成案件能够完成端到端审查。
2. 关键事实、规则结果、风险项和报告结论均可追溯到材料、制度、工具结果或人工决策。
3. 材料矛盾不由模型自动裁定。
4. 确定性计算和规则不交给 LLM 心算。
5. 发生外部服务失败、Worker 中断或人工暂停后可以恢复。
6. 所有功能均有 Test Case ID，测试结果和证据可记录。

## 4. 用户与权限

PoC 不建设真实登录系统，使用两个服务器端固定映射的演示用户，通过 Vue 顶部角色切换器切换。

| 能力 | RM | Reviewer |
|---|---:|---:|
| 创建案件、上传和补充材料 | 是 | 否 |
| 启动新审查 Run | 是 | 否 |
| 查看进度、材料问题和退回原因 | 是 | 是 |
| 查看完整事实、规则、风险和报告草稿 | 否 | 是 |
| 裁定材料矛盾、修订事实 | 否 | 是 |
| 确认或退回报告草稿 | 否 | 是 |
| 恢复技术性失败任务 | 是 | 是 |
| 查看已确认报告 | 是 | 是 |

报告确认只表示“AI 辅助审查草稿已复核”，不代表授信批准、拒绝或额度决策。

## 5. 端到端业务流程

```text
RM 创建案件并上传材料
  → 系统校验格式、大小、数量和材料版本
  → RM 启动审查 Run
  → Worker 解析材料、抽取并归一事实
  → 系统检查完整性、证据有效性和跨材料矛盾
  → 有异常：HITL-1 等待 Reviewer 裁定
  → 无异常或裁定完成：检索制度、调用只读工具、执行规则
  → LLM 在证据约束下生成风险解释
  → 程序生成固定结构报告草稿
  → HITL-2 等待 Reviewer 确认或退回
  → 确认后生成 Web 报告和 Markdown 导出
```

补件、材料版本变化或报告退回必须创建新 Run。旧 Run、旧事实快照、规则结果、人工决策和报告不可覆盖。

## 6. 演示案件

### 6.1 正常案件 DEMO-NORMAL-001

- 四类必需材料完整且可解析。
- 关键事实跨材料一致。
- 10 条规则结果无 FAIL 或 NEEDS_REVIEW。
- 不触发 HITL-1，自动进入规则与风险分析。
- 必须在 HITL-2 等待 Reviewer 确认报告。

### 6.2 高风险案件 DEMO-HIGH-001

- 授信申请书中的申请期限为 24 个月。
- 尽职调查报告中的申请期限为 48 个月。
- 系统识别为关键字段实质矛盾并在 HITL-1 暂停。
- Reviewer 选择 48 个月为采用值，并填写裁定原因。
- 规则 R07 命中“申请期限不得超过 36 个月”，结果为 FAIL。
- 报告显示原始冲突、人工裁定、失败规则和制度依据。
- HITL-2 确认不等于授信审批通过。

## 7. 材料范围

每个演示案件至少包含：

| 材料类型 | 样本格式 | 解析路径 |
|---|---|---|
| 营业执照 | 扫描 PDF | MinerU API 兜底 |
| 授信申请书 | DOCX | python-docx |
| 尽职调查报告 | 文本 PDF | PyMuPDF；低质量时 MinerU |
| 财务报表 | XLSX | openpyxl，读取公式缓存值 |

上传约束：

- 仅允许 `.pdf`、`.docx`、`.xlsx`。
- 单文件不超过 20MB；一个案件同时处于“当前有效”状态的材料版本最多 10 份。
- 被新版本替代的历史材料不计入 10 份上限，但必须永久保留以复现旧 Run。上传后若当前有效材料将超过 10 份，整次请求拒绝且不产生文档记录。
- 拒绝 `.doc`、`.xls`、`.docm`、`.xlsm`、独立图片及扩展名/MIME 不一致文件。
- 加密或需要密码的 PDF 不收集密码，直接标记不可用并要求重传。
- 同类材料重传生成新版本，不覆盖旧文件和旧解析结果。

## 8. 标准事实字段

PoC 固定抽取以下 15 个字段，每个字段必须携带规范值、原始值、来源文档版本和证据定位：

| 编号 | 字段 | 规范类型 |
|---|---|---|
| F01 | 企业名称 | string |
| F02 | 统一社会信用代码 | string |
| F03 | 成立日期 | ISO date |
| F04 | 法定代表人 | string |
| F05 | 所属行业 | enum/string |
| F06 | 申请金额 | Decimal，单位元 |
| F07 | 币种 | ISO 4217，PoC 默认 CNY |
| F08 | 申请期限 | integer，单位月 |
| F09 | 贷款用途 | enum/string |
| F10 | 总资产 | Decimal，单位元 |
| F11 | 总负债 | Decimal，单位元 |
| F12 | 流动资产 | Decimal，单位元 |
| F13 | 流动负债 | Decimal，单位元 |
| F14 | 营业收入 | Decimal，单位元 |
| F15 | 净利润 | Decimal，单位元 |

LLM 负责从非结构化内容映射到结构化 Schema；日期、金额、单位、期限、百分比和枚举归一由程序执行。LLM 自报置信度不作为人工复核依据。

## 9. 矛盾与人工裁定

- 统一社会信用代码、申请期限、日期和规范枚举采用精确比较。
- 金额及财务数值只有在差异同时超过 1% 和 10,000 元时才构成实质矛盾。相对差异定义为 `abs(a-b) / max(abs(a), abs(b))`；当两值均为 0 时相对差异为 0。
- 证据缺失、Schema 无效、必填事实缺失、OCR 质量不可用或实质矛盾均可触发 HITL-1。
- 系统展示所有候选值、来源、证据位置和差异，不设置自动权威来源。
- Reviewer 可以选择某个来源值，或录入修订值；录入修订值时必须填写原因。
- 原始值、采用值、操作者、时间、原因、证据及前后快照版本必须保留。

## 10. 制度与规则范围

PoC 使用 5 份纯合成 PDF 制度：客户准入、贷款用途、额度期限、财务指标、行业与风险名单。

首版规则包固定为：

| ID | 规则 | 结果来源 |
|---|---|---|
| R01 | 四类必需材料完整 | 文档元数据 |
| R02 | 企业成立年限不少于 1 年 | F03 + 程序日期计算 |
| R03 | 行业不属于禁止准入 | F05 + 行业制度 |
| R04 | 黑名单查询结果为否 | `check_blacklist` |
| R05 | 客户风险状态正常 | `get_customer_profile` |
| R06 | 流动资金贷款用途在允许范围 | F09 + 用途制度 |
| R07 | 申请期限不超过 36 个月 | F08 + 期限制度 |
| R08 | 申请金额不超过可用授信额度 | F06 + `get_credit_exposure` |
| R09 | 资产负债率不超过 70% | F10、F11 + 程序计算 |
| R10 | 流动比率不低于 1.0 | F12、F13 + 程序计算 |

规则精确定义：

- **R01 材料完整性**：营业执照、授信申请书、尽调报告和财务报表各存在一个当前有效版本且状态为 `PARSED` 时 PASS；类型缺失或材料被拒绝时 FAIL；文件已存在但解析或关键证据不可用时 NEEDS_REVIEW。
- **R02 成立年限**：Run 创建时固化 `review_date`。当 `review_date >= establishment_date + 1 calendar year` 时 PASS，否则 FAIL；2月29日成立企业在非闰年的周年日按2月28日计算。成立日期缺失、晚于审查日或无效时 NEEDS_REVIEW。
- **R03 行业准入**：`ALLOWED → PASS`、`RESTRICTED → WARN`、`PROHIBITED → FAIL`；未知或无法映射时 NEEDS_REVIEW。
- **R04 黑名单**：`matched=false → PASS`、`matched=true → FAIL`；空值、超时或无效返回 NEEDS_REVIEW。
- **R05 客户风险状态**：`NORMAL → PASS`、`WATCH → WARN`、`HIGH_RISK → FAIL`；未知或工具失败时 NEEDS_REVIEW。
- **R06 贷款用途**：规范用途属于制度允许集合时 PASS，属于禁止集合时 FAIL，无法归一或制度证据缺失时 NEEDS_REVIEW。
- **R07 期限上限**：期限为正整数且不超过36个月时 PASS，超过36个月时 FAIL；缺失、非整数或不大于0时 NEEDS_REVIEW。
- **R08 可用额度**：申请金额与工具返回额度均为 CNY 且 `requested_amount <= available_amount` 时 PASS，超过时 FAIL；任一金额为负、币种不一致、工具失败或值缺失时 NEEDS_REVIEW。PoC 不执行汇率换算。
- **R09 资产负债率**：使用 Decimal 计算 `total_liabilities / total_assets × 100%`；结果不超过70%时 PASS，否则 FAIL。总资产不大于0、总负债为负或字段缺失时 NEEDS_REVIEW。
- **R10 流动比率**：使用 Decimal 计算 `current_assets / current_liabilities`；结果不低于1.0时 PASS，否则 FAIL。流动负债不大于0、流动资产为负或字段缺失时 NEEDS_REVIEW。

结果枚举为 `PASS | WARN | FAIL | NEEDS_REVIEW`。案件汇总状态按以下优先级生成：存在 NEEDS_REVIEW 时为 `REVIEW_BLOCKED`；否则存在 FAIL 时为 `NON_COMPLIANT`；否则存在 WARN 时为 `WARNING`；其余为 `PASS`。`REVIEW_BLOCKED` 时不得确认报告，必须先通过补件、人工裁定或可重试恢复消除不确定项。该汇总仅描述审查状态，不构成授信审批结论。

## 11. 报告范围

报告采用固定模板，至少包含：案件摘要、材料状态、关键事实与冲突、10 条规则结果、财务指标、风险项、制度依据、工具状态、人工记录、局限和待办。

- 程序填充事实、数值、规则、证据和人工记录。
- LLM 只生成摘要和有证据约束的风险解释。
- 风险级别固定为 HIGH、MEDIUM、LOW。
- 风险项必须绑定事实、规则、制度或工具证据。
- 无法验证的内容标记 UNSUPPORTED，不得进入正式结论。

## 12. Acceptance Criteria

- AC-002-01：正常案件完成从上传到报告确认的闭环，且不触发 HITL-1。
- AC-002-02：高风险案件准确识别期限冲突，未经人工裁定不得执行依赖该事实的最终规则判断。
- AC-002-03：Reviewer 裁定 48 个月后，R07 必须返回 FAIL 并引用期限制度。
- AC-002-04：报告确认前 RM 不得查看完整草稿，Reviewer 可以查看并操作。
- AC-002-05：补件或退回产生新 Run，旧 Run 可复现且不可覆盖。
- AC-002-06：工具失败不得被解释为 PASS 或 FAIL，必须返回 NEEDS_REVIEW 并阻断报告确认。
- AC-002-07：所有正式结论均有证据，UNSUPPORTED 内容被隔离。
- AC-002-08：确定性规则、两条 E2E、HITL、恢复和安全硬门槛全部通过。

## 13. 明确不做

- 真实客户数据和生产系统连接。
- 最终授信审批、自动额度决策和放款。
- 真实认证、制度管理后台、规则管理后台和审计时间线页面。
- 担保规则、房地产/项目融资/并购等复杂授信。
- MCP、模型自主工具选择和自治多 Agent 对话。
- PaddleOCR、旧版 Office、独立图片、任务运行中取消。
- PostgreSQL、Milvus、Redis、MinIO、Celery、Docker Compose 和生产高可用。
